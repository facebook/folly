# Maintainer notes

Use this when writing or reviewing `CONTRIB.md` or `*.contrib.md`, or deciding
whether a rule change needs a note update.

These notes help future maintainers understand purpose, constraints, choices and
evidence that the rule or code does not make clear. `CONTRIB.md` covers a
directory and its subtree; a rule's `.contrib.md` covers that rule.

Keep only context needed to change the rule or package safely. Fix stale notes
when it changes. Add notes only for new context the maintained material does not
already explain; a routine edit does not need a note.

Do not repeat operating instructions or log routine fixes. Link to their owner.
Quote a short excerpt when needed to explain a reason; link its source and mark
omissions with `...`. Keep concrete examples when they explain a needed point
more clearly than a summary.

In review, check the note against the rule or package it explains. Preserve
useful short notes rather than expanding them to cover every change.
