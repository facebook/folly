> NOT A RULE. If loaded as task policy, stop and ask the user.

The rule helps writers and reviewers give readers a useful introduction before
they open the diff. "Summary" is a legacy label for that introduction. It gives
the practical reason for the work and the main approach.

Readers know software development, but may not know this code or its discussion.
Details matter when they help readers follow the approach or see why a choice
was made. An implementation tour can hide that framing.

Review should improve poor introductions while preserving useful brief ones.
More detail helps when it fills a gap in the reader's understanding, not merely
when it adds another fact from the diff.
